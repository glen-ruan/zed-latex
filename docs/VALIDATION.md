## 编辑测试材料

将以下定义放在临时项目的导言区，其余位置留作手动输入补全前缀或测试调用：

```tex
\newcommand{\demo}[2][default]{#1#2}
\NewDocumentCommand{\modernDemo}{s O{choice} m}{#3}
\newenvironment{demoenv}[2][default]{#1#2}{}
\NewDocumentEnvironment{modernenv}{O{choice} m}{#1#2}{}
\newtheorem{demotheorem}{示例}
\newcommand{\readDemo}[1]{\input{#1}}
\NewDocumentCommand{\readOuter}{O{unused} m}{\readDemo{#2}}
```

同目录另放普通内容文件，用来测试 readDemo/readOuter。内容文件使用 % !TeX root = master.tex 时，主文件必须真实存在。

## 构建和错误恢复

在临时项目中集中完成：

1. 首次构建，确认主文件与根目录 build 输出。
2. 修改子文件后直接构建，确认无需先 Clean，未保存提示符合预期。
3. 外部阅读器占用 PDF 制造失败，关闭后再次构建，确认恢复和日志。
4. 制造子文件错误，确认诊断定位；修复并构建后诊断清除。
5. 多个主文件共用子文件时，相关诊断保留到各自主文件恢复。
6. 查看日志、进度和耗时，运行 Clean 并核对清理范围。
7. 验证格式化结果，不修改编译入口或项目设置。

沿用既有构建设置。本轮未扩展 PDF 预览/联动、自动编译机制或平台兼容矩阵。
